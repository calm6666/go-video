# 运维与发布文档

## 1. 环境

| 环境 | 用途 | 原则 |
|---|---|---|
| local | 开发和单元/集成调试 | 只启动必要依赖，使用测试桶和种子数据 |
| test | 联调和回归 | 独立数据库、Topic、Redis key 前缀和密钥 |
| staging | 发布前验证 | 接近生产拓扑，演练迁移、回滚和限流 |
| production | 正式流量 | 托管依赖、跨可用区、备份和恢复演练 |

## 2. 配置

配置分为非敏感配置和 Secret：端口、超时、Topic、依赖地址可进入配置中心；密码、JWT 密钥、OSS 密钥、第三方审核凭证必须进入 Secret/Vault。配置变更要审计、可回滚，服务启动日志不得打印 Secret。

## 3. 健康与发布

- `/healthz` 只表示进程存活；`/readyz` 检查必要依赖。
- 关闭时先停止接收新请求，再等待 HTTP/RPC、MQ consumer 和转码任务安全退出。
- 无状态服务使用滚动发布；转码/事件消费者使用租约和优雅再均衡，避免重复处理。
- 数据库迁移先在 staging 验证，再发布兼容代码，最后执行不可逆清理。

## 4. 监控指标

平台：CPU、内存、GC、连接池、RPC 延迟、错误率、限流、MQ lag、Redis 命中率、MySQL 慢查询。业务：上传成功率、转码排队/失败率、首帧时间、卡顿率、直播延迟、审核积压、评论/弹幕发送成功率、搜索延迟、推荐召回和排序耗时、SPM 事件接收率、通知成功率。

每条请求、异步任务和跨服务事件带 `trace_id`；关键操作写结构化审计日志。告警必须关联 runbook 或处理人，不使用“日志出现字符串”作为唯一 SLO。

## 5. 备份与恢复

- MySQL 做全量+binlog，定期恢复验证；Redis 按用途决定持久化，缓存允许重建。
- 对象存储启用版本/生命周期策略，转码临时文件自动清理，源文件删除需审计确认。
- MQ 保留周期按重放需求设置；事件 schema 和关键 Outbox 数据不能随业务日志一起删除。
- 每季度演练内容发布回滚、版权撤回、转码队列堆积、搜索索引重建和 SPM 延迟恢复。

## 6. 常见故障处理

1. 转码积压：限制新任务、扩容 Worker、检查对象存储和 FFmpeg 资源，失败任务按幂等键重试。
2. 播放异常：检查 playback 签名、CDN 回源、Variant 状态和版权窗口，不直接把 OSS 设为公共桶。
3. 事件积压：查看生产端 Outbox、Topic lag、消费者错误和死信；先恢复消费，再补偿投影。
4. 推荐异常：降级到热门/关注流；保留原始事件，待 SPM/特征恢复后回填。
5. 审核不可用：新投稿进入待审核，不得默认放行；已发布内容按风险策略降级。
